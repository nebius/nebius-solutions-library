# Nebius BioNeMo

Use the Nebius BioNeMo MCP server instead of calling NIM HTTP endpoints directly.
The server exposes tools only for enabled models that passed their startup readiness
probe. Start each session with `list_models`; use `fleet_health` when a requested
tool is absent or a model call fails.

## Select A Tool

- `boltz2_predict`: protein, nucleic-acid, ligand, and complex structure prediction;
  use its affinity fields for protein-ligand ranking.
- `openfold2_predict`: protein-only structure prediction where OpenFold2 compatibility
  is required.
- `openfold3_predict`: protein and biomolecular complex structure prediction; accepts
  an MSA generated by the fleet.
- `diffdock_dock`: ligand docking against a supplied receptor structure.
- `genmol_generate`: de novo small-molecule generation from molecular constraints.
- `molmim_run`: controlled molecular generation and optimization around a seed.
- `msa_search`: create alignments for downstream structure prediction.
- `rfdiffusion_generate`: generate protein backbones from structural constraints.
- `proteinmpnn_design`: design protein sequences for supplied backbones.
- `evo2_run`: score or generate biological sequences with Evo2.
- `msa_structure_prediction_pipeline`: run MSA Search and feed its alignment to
  OpenFold3.
- `drug_discovery_pipeline`: generate candidates with GenMol, dock them with
  DiffDock, then rank selected candidates with Boltz2 affinity prediction.

Inspect each tool's MCP schema before calling it. External NIM references provide
scientific context, while the MCP schema is the execution contract for this
deployment; do not invent fields that the schema does not publish.

## Capacity And Warm-Up

BioNeMo tools run on GPU-backed NIM pods. B200 nodes and NIM replicas can take
several minutes to provision, pull images, load model weights, and become ready.
An absent tool means its model was disabled or unhealthy when that MCP process
started; check `fleet_health` and let the operator restart the gateway after the
model is ready. Parallel model calls can trigger additional GPU replicas and cloud
cost. Prefer a small representative request first, avoid unbounded candidate
counts, and use the composed pipelines when their bounded orchestration matches the
experiment.

## Artifacts

Tool results contain compact summaries and artifact records with a presigned HTTPS
URL, SHA-256 checksum, media type, and expiry. Download every artifact needed for
reproducibility before its URL expires:

```bash
nebius-bionemo-download result.json --run-dir runs/<experiment-name>
```

Use a new run directory per experiment. The downloader rejects redirects and
verifies checksums. Every run includes the validated tool input in `request.json`
and the complete backend output in `response.json`. Keep the original MCP result
JSON beside the downloaded files so model versions, returned metadata, and
artifact hashes remain auditable.

## Scientific Use

Treat predictions as research outputs, not clinical conclusions. Record model and
image versions from `list_models`, preserve complete inputs and artifacts, compare
confidence and ranking fields only within their documented meaning, and validate
important results with independent computational or experimental methods.
